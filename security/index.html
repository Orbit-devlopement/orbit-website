Security and access

Know what ORBIT can access.

Security boundaries should be understandable. These describe the current pilot architecture, not an independent security certification.

Authentication

The private application uses Supabase authentication and an approved-user list. A verified second factor (MFA) is required for private workspace features.

Read-only integrations

GitHub and GitLab repository connections are accessed by authenticated server functions. Provider tokens are designed to be encrypted with AES-GCM before storage and are never intended for display after connection.

The connector limits upstream requests to known GitHub.com and GitLab.com APIs using GET operations. Read-only API access does not make a broader provider token harmless: choose the narrowest possible permissions and short expiry dates.

Agent boundaries

The V5 agent job queue is approval-gated. Execution is restricted to an explicitly authorized operator with a local worker. Customer accounts are not automatically granted code execution.

What we have not completed

  • An independent penetration test or formal security certification.
  • Production-ready OAuth account linking and automated token rotation.
  • Public self-service subscriptions or enterprise account administration.
  • Production incident response and contractual service-level commitments.
ORBIT is an invite-only pilot. Do not assume enterprise certification, compliance audits, or production SLAs.

Security questions

Security inquiries and pilot invitations are not yet open. A verified contact method will be published before customer onboarding.
